# Test-Driven Development

Le cycle TDD est :

1. **RED** : écrire un test qui échoue pour la raison attendue.
2. **GREEN** : écrire le minimum de code nécessaire pour le faire réussir.
3. **REFACTOR** : améliorer la conception sans changer le comportement.

## Règles

- Le test exprime un comportement attendu.
- Le test précède l'implémentation lorsque le contexte le permet.
- L'implémentation reste minimale.
- Le refactoring conserve les tests verts.
- Ne pas affaiblir ou supprimer un test uniquement pour faire passer le code.
- Adapter la démarche pour les tâches purement documentaires, exploratoires ou de configuration lorsqu'un cycle TDD n'a pas de sens.
